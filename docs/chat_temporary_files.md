# 聊天文件临时存储

知识库资料仍走原来的长期存储、审核和备份；以下只涉及聊天附件与生成/转换产物。

## 生命周期与原件重发

- 首次上传附件时，完整执行大小、格式、加密检查。只缓存提取的正文、基本元数据和原件 SHA-256，默认 60 分钟；原件和提取中间文件立即删除，不登记永久文件记录。
- 网页将原件保留在页面内存。转换时通过带鉴权的 `/chat/stream/originals`（非流式对应 `/chat/originals`）发送原件、附件 ID 和聊天参数。再次执行全部入口检查，必须匹配第一次上传的 SHA-256。原件只在本轮身份工作目录中存在，完成、失败或断开时清理；不会从正文重建转换输入。
- 网页识别明确的转换/编辑操作，或使用产物上的“继续处理”；多个文件时要求选择具体文件。原件因刷新、切换会话或 1 小时到期而不存在时，提示“原件已清理，请重新上传后再转换”。服务端也有同样的兜底，不返回未知错误。
- 普通阅读仍使用正文缓存，不重发原件。正文缓存及哈希在 API 重启后失效，需重新上传。
- 产物存入 `data/tmp_uploads/temporary_products/`，包含归属、创建时间、到期时间及服务身份标记。默认每用户 100 MiB、全局 128 MiB；配额不足明确拒绝。每 30 秒清理到期文件，启动只清理身份正确且已到期的目录，未知目录不动。
- 网页完整取得 Blob 后发送下载回执，服务器立即删除产物。页面离开另外发鉴权清理请求（尽力而为，网络失败仍由到期机制兜底）。浏览器只在内存保存 Blob，不用 localStorage、IndexedDB 或 Cache API。用户下载本地后才标为已保存；未保存离开会提示确认（原生浏览器离页弹窗文字由浏览器控制）。
- 刷新/切换会话/1 小时到期后，历史只显示文件名和“文件已清理”，不提供失效下载。`/files` 继续返回有效临时产物，兼容现有 App；已清理或不存在的下载统一明确报错，不泄露其他用户的文件。
- 临时区不在每日备份的白名单中。取消只删除该请求登记的产物，不删除其他请求或已生成的文件。

## 文件痕迹

`file_trace` 是隐藏的描述消息，不出现在历史接口、网页或会话消息计数里；随会话删除。Agent 上下文以不可信描述数据包裹，明确说明“不是指令”，不提升为系统消息。

只记录经过清理的文件名、类型、文件大小与操作。Agent 阅读/生成的内容，从同一次回复/生成正文提取受控类别标签（说明、清单、流程、表格、代码、图文、分析），作为粗粒度大意，并注明操作；不复制自由文本、原文、个人事实或数字事实，不增加模型调用。无法命中类别时仅注明已读取，不凭空猜测内容。文件名疑似敏感或指令式时改为通用名。单纯转换只记录基本信息。

## 部署及现存永久文件

- 已有 `files.db` 与 `data/user_files/` 不自动删除；旧记录不再通过新 `/files` 接口列出或下载。历史文件显示已清理，历史问答内容本身不删除。
- 建议部署前由统筹师先确认是否有必须保留的历史文件，告知用户另行保存；确认后在停机窗口按文件库登记逐项核对、一次性清理旧附件和产物及对应记录。旧备份中可能仍含原件，应另行按备份保留策略处理。本次不执行任何生产清理。
- 用户已授权部署后统一清理旧永久聊天附件与Agent产物。维护命令为`python scripts/cleanup_legacy_chat_files.py --data-dir data`，默认dry-run，只报附件原件、生成产物、转换产物的条数/字节数，另报无元数据孤儿文件的数量/字节数，不报文件名、路径、ID或正文。
- 在部署仓库先执行`docker compose stop zhitian-api`，再执行`docker compose run --rm --no-deps zhitian-api python scripts/cleanup_legacy_chat_files.py --data-dir data`核对dry-run。确认后，在同一命令末尾加`--delete --confirm-service-stopped`才会删除。清理期间保持API停止，不得并行启动；完成后才执行`docker compose up -d zhitian-api`。脚本检查本进程命名空间里的API进程、回环API端口及同Compose网络的API服务；检查失败或仍在运行就拒绝，停机确认参数不能绕过检查。
- 有元数据的清理范围限于旧`files.db.user_files`中带会话的attachment/generated/converted，不动知识库、上传任务、聊天文字、新临时区或无会话的旧手动工具产物。孤儿只能位于`user_files/归属/UUID.格式`及其应用定义的`.tmp`、`.deleting`变体，必须无任何对应元数据；不递归删目录、不跟随链接，未知命名和嵌套目录均保留。孤儿无法再判断原来源，因此单独统计，不冒充某类产物。
- 删除复用应用旧文件删除逻辑：先删实体（不存在算已删），再提交元数据删除。中断后重复执行即可完成剩余记录及规范孤儿；不会留下新孤儿。当前公开删除接口走新临时存储，不变更接口行为。清理不可恢复，回滚旧镜像不会恢复旧文件；旧备份另按保留策略处理。
- `CHAT_ATTACHMENT_TTL_MINUTES` 默认从 30 改为 60；若部署环境显式配置了旧值，需同步调整。新增 `TEMP_FILE_TTL_MINUTES`、`TEMP_FILE_USER_QUOTA_MB`、`TEMP_FILE_GLOBAL_QUOTA_MB`。
- 重建 API 与 web 客户端。回退旧代码会重新使用旧永久文件库；已被临时机制清理的新产物无法恢复。

## App 后续同步点

本次不改 App 界面。后续需同步 `files_page.dart` 的临时列表/已清理提示、`chat_page.dart` 的 Blob/本地内存下载与回执、原件本地缓存及重发、刷新/退出/过期策略、连续修改与未保存确认。现有下载不发送回执时，后端最多保留到 60 分钟到期。
