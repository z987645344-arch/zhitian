# TXT / MD 临时编辑

网页附上一个 UTF-8 编码的 txt/md 文件，点“编辑此文件”，再写修改要求。
“继续处理”使用浏览器中当前版本重新上传；txt/md成品明确进入编辑，不在服务器保留跨轮原件。

- 入口 `agent_chat`、任务 `edit`，注册表只允许 txt→txt、md→md。
- 原件重传复用大小、格式、加密检查及首次上传的 SHA-256 校验。
- 模型只提议 replace / insert_after / delete，锚点必须逐字且唯一；重叠操作拒绝。
- 默认原文和成品最多 50,000 字符、20 条操作、改前与改后合计 20,000 字符。
- 总共最多两轮模型调用：初次方案和一次纠错；纠错仍以不可变原文为基准。
  第二轮仍不合法时，只交付校验通过的修改，明确列出未完成项；全部失败则不生成文件。
- 只用 fast 档编辑计划器，不分类、不查知识库、不联网、不判定长期记忆重要性。
  阶段 `text_edit_plan` 默认 high 推理，独立 `TEXT_EDIT_TIMEOUT` 默认90秒，
  两轮计划、核验和交付共享总预算，不另加超时重试。超时请缩短文本或拆分要求。
- UTF-8 BOM、原有换行和未修改的文字保留。明确删除全部文字可产生合法空文本。
- 对照只随本次响应交付、不进入历史；隐藏痕迹只记录受控操作类别，不复制原文。
- 原件/中间产物本轮结束即清理；成品复用临时配额、回执即删、60分钟到期与取消清理。
  浏览器仍是内存 Blob，刷新、切换对话或一小时后失效，未保存离开前提醒。
- 任务日志只有编号、操作数、结果、耗时；文件内容是数据，不授予命令或文件访问权限。

部署重建 API 和 web，现有数据不需迁移。配置项使用默认值即可。
App 本轮没有编辑入口；不改变其既有普通聊天和临时文件接口。

## 固定小测

`tests/eval/run_text_edit.py --prepare-only` 只打印计划，不启动应用或调用模型。
五个虚构任务最多 10 次逻辑调用，HTTP hook 在每次发送前记账、硬上限 12 次（含重试）。
使用项目 `.venv`，真实走附件上传、原件回传、SSE、下载与回执；库在仓库外临时目录，
结果写入被忽略的 `backups/eval/`，不联网、不判卷。样本在脚本中固定，结果不得提交。
