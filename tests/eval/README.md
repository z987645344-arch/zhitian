## 公司设定

“岚屿栖盒 EVAL-Q7”是为本评估专门编造的商店代号，不指代真实企业。虚构产品为舟灯L1、舟灯L2、栖温杯C1。所有制度、金额、示例订单、会员权益与服务时间均为虚构，不能作为真实交易或法律建议。没有摘录法律条文，也没有生产数据、真实账号、电话、邮箱或服务地址。

制度有意包含关联与易混淆信息：普通区/远程区首重12/22元；L1/L2/C1保修12/24/6个月；包装重量与净重不同；延保购买窗口、质量换货窗口和保修期彼此独立；积分抵扣会影响300元免运门槛。应用示例只说明规则，不证明真实订单状态。

## 题目契约

`questions.json` 共50个题目单元：单点事实20、跨文档/多跳10、拒答10、部分命中5、多轮5组。多轮分别3或4轮，展开后总计62轮。拒答按内部事务5题、公开常识5题划分。

- `question`：单轮字符串；多轮为按顺序发送的字符串列表。
- `expected_behavior`：answer/refuse/partial。
- `expected_points`：事实与约束，不要求照抄措辞；算术题允许计算，但不允许补造输入。
- `forbidden`：禁止被当成事实或建议肯定输出的内容；在否定、纠错或风险说明中引用该词不应机械判错。
- `expected_sources`：相对于`corpus/`的文件名。是支持正确结论的来源，不要求固定引用编号或完整排序。允许引用确实包含同一事实的其他语料，但不能用它替代缺失的跨文档证据。
- `supporting_evidence`：对应来源、条目编号、可核对原文。不是答案模板。
- 拒答题来源为空，不能给不存在的答案伪造引文；缺失是对整套固定语料的判定，不是某一段落的事实。
- 部分命中题用`unanswerable_points`标明缺失部分，回答须明确无法确认，不能用自身知识补齐。
- 多轮题的`expected_points`考查最后一轮；`turn_checks`记录每轮检查点。订单号、时间与诉求来自本组用户陈述；它们不是知识库或真实订单查询结果。仅制度结论需要文档引用。
- 每个题目/多轮组应使用独立会话；组内保留历史。不得将别组的演练订单事实带入本组。

## 本轮自查与边界

`manifest.json`保存8个实际文件的SHA-256、提取字符数、切片数与确定性自查数据。68条证据摘录均存在（PDF检查允许空白换行归一化）；20道单点题均有单个片段支持。跨文档题人工核对组合前提与计算。10道拒答题全文关键词命中均为0，结合全文审阅确认没有所问事实；关键词0命中本身不能替代语义审阅。

Windows原生项目`.venv`使用仓库外临时目录完成解析、切片、真实向量写入与实读计数，8份均成功，未经过LibreOffice转换。默认`data/`的16个文件在测试前后路径、大小、修改时间及SHA-256完全一致。网络连接与模型供应商入口在自查进程内禁止；GraphRAG和精排关闭，付费调用0。

两份PDF共8页已逐页渲染检查。DOCX结构、正文提取和向量入库通过；因bundled LibreOffice不可用，DOCX页面视觉检查未完成，用户已明确允许按此口径提交，视觉审核交给用户。

本轮没有运行问答评测、HTTP上传/审核全链路、模型评分或回答质量基线；不把入库成功表述为检索/回答效果通过。未改应用VERSION、依赖或项目`.venv`。之后的前后对比须固定此语料和题目；如修改数据，另起数据集修订并重新记录文件校验和。
