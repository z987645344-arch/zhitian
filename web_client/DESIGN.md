# 知天三端公共组件规格

2026-09-12 · 以 customer 既有暗色令牌为基准，不引入远程字体或构建链。此规格描述显示层，不改变角色能力、请求字段或错误码。

## 基础

背景 `#20292e`，表面 `#29343a`，低表面 `#172025`，高表面 `#344047`；正文 `#eff2f3`，说明 `#b7c0c3`，辅助 `#929fa4`。主操作灰绿 `#b3b7a4`，深色按钮文字 `#20292e`；错误 `#dc9188`、警告 `#d8b071`、成功 `#9bbcaf` 各有独立低亮度底色。所有端使用本地系统字体，编号与技术字段用 mono。正文 15–16，辅助 12–13，分区标题 20–24，页面标题 32–44；营销说明可至 68。间距 4 / 8 / 12 / 16 / 24 / 32 / 64；圆角 10 / 16 / 24。圆形「知」40，不改变首页链接语义。

| 公共组件 | 显示规范 | 使用边界 |
|---|---|---|
| 按钮 | 主按钮灰绿实底；次按钮低表面细线；危险按钮红字暗红底。点击区至少 44，移动端可纵排 | 一页一个主要目的；请求中继续使用原禁用逻辑 |
| 输入框 | 常驻标签、深底细线、明确聚焦轮廓；placeholder 走辅助色令牌 | 校验文字紧邻字段，密码 / Key 不回显、不进入浏览器存储 |
| 卡片 | 16 圆角与一条细线，24–32 内距，少用阴影；10 留给小控件，24 留给外层容器 | 无数据也不伪造统计；当前选中状态同时有文字和边框 |
| 状态标签 | 状态词始终存在，颜色只是辅助；普通状态低对比背景，错误 / 警告清晰区分 | 不把“不可达”写成“没有数据”，不把未知写成正常 |
| 空状态 | 一句说明这里会有什么，一句给出现在能做的动作 | 不承诺未实现的功能，不为历史死代码补页面 |
| 错误提示 | “发生什么 + 下一步”，长诊断放展开区；消息独立于聊天正文 | 登录失败：“登录未成功，请核对账号信息后重试。”；过期：“登录已过期，请重新登录后继续。”；无权限：“当前账号没有此操作权限，请联系管理员确认。”；超时：“连接超时，请检查网络后重试。”已有服务端具体错误与接口错误码保持原样，不做全局覆盖 |
| 编号导航 | mono 的 01 / 02 与直白名称并排；当前页同时有选中态与名称 | 顺序反映操作流程，不暗示新能力；角色已有导航钩子原名保留 |

## customer 页面现场记录

登录与注册：放大标题、保留圆形标记，移动端也显示精简产品说明；注册先说明用途，再给密码与验证码约束。每页保留一个主 h1。对话与设置加编号；设置两种额度是互斥方案而非必须依次完成的步骤，因此标为“方案 01 / 02”，仍由真实 source 状态说明当前选择。

引用、执行动态、请求降级使用原生 details / summary：默认一句话，展开保留文件、doc_id、score、chunk、执行耗时与原因。流式请求与事件字段不变，用户文本仍使用 textContent。已有脚本钩子不改名。四页资源版本统一 `archive-ui-20260912`。
